Agentic Enterprise

업무 Application, 공통 지식 기반, 검증과 승인 절차를 함께 설계합니다. 전문 Agent는 담당 업무에 필요한 지식과 도구를 사용하고, 결과를 다음 업무로 연결합니다.

기업의 공통 지식 기반

여러 업무가 연관된 요청은 Coordinator가 전문 Agent에 전달합니다. 각 Agent는 같은 지표와 규칙을 참조하고, 정해진 검증·승인 절차에 따라 결과를 업무에 반영합니다.

Domain-Specific Agents

업무의 전문성·책임·권한에 맞춰 구성합니다

하나의 거대한 Agent에 모든 업무·도구·권한을 집중하지 않고, 필요한 전문 업무를 Coordinator로 연결합니다. 실제 Agent 수는 업무 요구와 평가 결과로 정합니다. 단순한 업무에는 단일 Agent나 정해진 절차만으로 충분할 수 있습니다.

Different decisions require different agents.

수익성 분석과 공급계획은 필요한 지식·계산·변경 권한이 다릅니다. 이 차이를 분리 기준으로 사용합니다. 원인 분석·예측·시뮬레이션이라는 질문 유형마다 Agent를 하나씩 만들지는 않습니다.

문맥·책임·권한의 범위 정렬

Context Boundary = Responsibility / Permission Boundary는 같은 업무 범위에 맞추는 설계 원칙입니다. 문맥 자체가 보안을 보장하지는 않습니다. 데이터 서비스와 도구가 실제 권한을 확인하며, Coordinator가 모든 Agent의 권한을 자동으로 갖지 않습니다.

AI-ready Data Model과 Knowledge Layer

AI-ready Data Model은 업무 객체의 식별자·관계·집계 단위·상태·이력·유효 시점을 실제 데이터에 연결합니다. 예를 들어 가용 재고는 어느 창고와 시점 기준인지, 예약·확정수주·입고 예정이 어떻게 반영되는지를 명시해야 합니다.

Knowledge Layer는 업무 지식과 데이터를 제공하는 논리 계층입니다. Graph 질의·검색·Semantic View를 업무에 맞게 조합하며, 조회할 때 권한·출처·버전을 확인합니다. 지표 정의와 계산 구현은 연결해 관리하되 같은 내용을 중복 저장할 필요는 없습니다.

Decision / Control Loop

관찰 → 판단 → 실행 → 검증 → 지식 개선

계산과 규칙 처리는 검증된 도구에, 해석과 탐색은 Agent에 맡깁니다. 사전 허용된 작업은 자동 처리하고 정책이 요구하는 변경은 승인 후 실행합니다. 실행 결과와 반복 예외는 검토·평가를 거쳐 지식과 운영 기준에 반영합니다.
