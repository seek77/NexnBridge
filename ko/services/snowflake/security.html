도입 전에 통과해야 하는 관문

누가 어떤 데이터를 볼 수 있는지
먼저 정합니다

데이터를 한곳에 모으면 접근 범위를 다시 설계해야 합니다. 특히 Agent가 데이터를 조회하기 시작하면 사람 기준으로 만든 권한 체계만으로는 부족합니다.

이런 상황에 필요합니다
  • —데이터를 통합하면서 부서별·역할별 접근 범위를 다시 정해야 한다
  • —개인정보·거래정보 등 보호 대상 항목이 포함된다
  • —보안 검토를 통과해야 도입을 진행할 수 있다
  • —Agent가 어느 데이터까지 볼 수 있는지 정하지 못했다

새로 필요한 항목

Agent 권한 설계

기존 보안 설계는 사람이 화면에서 조회하는 것을 전제로 만들어졌습니다. Agent가 들어오면 다음 질문이 새로 생깁니다.

질문설계 방식
Agent는 누구의 권한으로 데이터를 조회하는가서비스 계정 권한을 별도로 두지 않고, 요청한 사용자의 권한 범위 안에서 실행되도록 설계합니다
Agent가 사용자보다 넓은 권한을 갖지 않는가사용자가 직접 조회할 수 없는 데이터가 Agent 답변으로 우회 노출되지 않도록 경계를 확인합니다
데이터가 어디까지 나가는가모델 호출 시 데이터가 어느 경계를 벗어나는지 확인하고, 필요한 경우 플랫폼 내부에서 처리되는 방식을 선택합니다
Agent 실행을 추적할 수 있는가어떤 도구를 호출하고 어떤 데이터를 참조했는지 기록을 남깁니다
중단 조건이 있는가권한 밖 요청, 비정상 사용량, 예외 상황의 중단·에스컬레이션 기준을 정합니다

Agent에게 권한을 주는 일은 사람에게
계정을 주는 일과 다릅니다.

Agent는 지치지 않고, 빠르며, 여러 데이터를 동시에 조합합니다. 그래서 개별 권한이 맞아도 조합 결과가 문제가 될 수 있습니다.

이 항목은 AgentOps의 Guardrail & Governance와 이어집니다. 여기서는 데이터 접근 권한을, AgentOps에서는 실행 통제와 감사를 다룹니다.
규제·내부 통제 대응

내부 보안 검토와 규제 요건에 필요한 설계 근거와 증적을 함께 정리합니다.

데이터 모델과 지표·계산 기준을 표준화해
현업 분석과 Agent가 동일한 정의를 사용하도록 합니다.

Snowflake 관련 공식 파트너·리셀러·자격 표기는 확인된 범위에서만 사용합니다. 기술지원의 범위와 SLA는 계약 시 명시합니다.
