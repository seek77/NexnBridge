AI Agent & Application Engineering

AI가 결과를 준비하고 현업이 검토·승인하도록
업무 흐름을 구현합니다

AI Agent & Application Engineering은 적용할 업무의 시작과 끝을 정하고, 필요한 데이터와 기준, AI Agent의 역할, 사람의 승인 지점을 연결합니다. 구현·검증·인수 범위는 현재 업무와 시스템 조건을 확인한 뒤 합의합니다.

적용할 업무 선정

에이전트의 기능부터 정하기보다, 시작과 끝이 분명한 업무 단위를 먼저 고릅니다

검토 요청이 들어온 시점부터 담당자가 승인하거나 보류할 때까지처럼, 어떤 사건으로 업무가 시작되고 어떤 결정이나 후속 조치로 끝나는지 확인합니다.

01 START

언제 시작하는가

어떤 요청, 데이터 변화 또는 예외가 이 업무를 시작시키는지 확인합니다.

02 CURRENT WORK

현재 무엇을 하는가

담당자가 어떤 자료를 모으고, 무엇을 계산하거나 비교하는지 살펴봅니다.

03 OUTCOME

결정 뒤 무엇이 달라지는가

승인·보류 이후 어떤 후속 업무나 시스템 상태가 바뀌는지 확인합니다.

04 OWNER

누가 검토하고 최종 승인하는가

결과를 검토할 담당자와 최종 승인자, 문제가 생겼을 때 중단을 결정할 책임자를 구분합니다.

선정 기준 — 처음부터 모든 조건이 정리되어 있을 필요는 없습니다. 아직 확인되지 않은 내용은 구현 전에 확인할 항목으로 남깁니다.

구현 전에 확인할 것

에이전트가 읽을 입력과 적용할 기준, 사람이 결정할 지점을 구분합니다

문서와 데이터가 연결되었다고 판단 기준까지 정해지는 것은 아닙니다. 입력의 의미와 상태를 확인하고 어떤 조건에서 어떤 규칙과 예외를 적용할지 따로 정합니다.

INPUT

업무 입력

요청 내용, 문서, 데이터, 현재 상태와 이전 처리 기록 가운데 필요한 범위를 정합니다.

DEFINITION

정의와 계산 방식

지표의 의미와 계산식, 단위, 기준 시점과 사용할 버전을 확인합니다.

RULE

규칙과 제약

적용 조건, 임계값, 우선순위, 허용 범위와 예외 처리 기준을 정합니다.

UNKNOWN

예외와 미확인 사항

입력 누락, 충돌하는 기준과 담당자의 추가 확인이 필요한 상황을 구분합니다.

AI 에이전트

담당자가 판단할 수 있도록 자료를 준비합니다

허용된 출처에서 입력을 찾고, 합의한 기준으로 계산·비교하며, 적용한 전제와 추가 확인 항목을 정리합니다. 확인되지 않은 값을 임의로 채우거나 승인받지 않은 기준을 적용하지 않도록 경계를 둡니다.

담당자와 승인자

업무 맥락을 검토하고 승인 여부를 결정합니다

입력과 출처, 적용 기준, 예외와 미확인 사항을 살펴보고 승인·보류·반려·추가 확인 중 필요한 조치를 선택합니다. 승인 권한을 구분하고 결정 내용도 기록합니다.

업무 지식 — 용어·규칙·출처가 정리되지 않았다면 Enterprise Knowledge를 먼저 진행하거나 구현과 함께 필요한 범위를 정할 수 있습니다.

구현 요소

필요한 요소만 골라 현재 업무와 시스템에 맞게 구성합니다

현재 화면과 업무 절차를 활용할 수 있다면 그대로 사용하고, 합의한 업무 흐름에 필요한 부분만 새로 구성합니다.

01 AGENT LOGIC

에이전트 처리 로직

사용할 출처와 도구, 기준 적용 방법, 결과와 미확인 내용을 표시할 형식을 정합니다.

02 REVIEW

검토 화면과 승인 조치

근거와 비교 결과, 예외를 확인한 뒤 승인·보류·반려할 수 있도록 화면을 구성하거나 기존 절차와 연계합니다.

03 INTEGRATION

데이터·시스템 연계

필요한 경우 파일·데이터베이스·API 등의 연결 방식과 인증·권한을 확인하고, 데이터를 읽고 쓸 범위를 정합니다.

04 WORK STATE

업무 상태와 알림

요청, 검토, 보류, 완료 상태와 담당자에게 알려야 할 조건을 정합니다.

05 ANALYSIS

분석과 계산

업무에 필요한 계산, 비교 또는 시나리오 분석이 있다면 사용할 기준과 검증 방법을 정합니다.

06 TRACE

기록과 추적

입력과 결과, 사용한 기준의 버전, 사용자와 승인 이력 가운데 남길 항목을 정합니다.

구현 범위 — 위 항목이 모두 포함되는 것은 아닙니다. 시뮬레이션, 최적화, 자동화와 시스템 연계는 업무 기준, 데이터와 권한을 확인한 뒤 필요한 경우에만 범위를 정합니다.

검증과 인수

정상 결과뿐 아니라 누락·예외 상황에서 어떻게 멈추는지도 확인합니다

구현 전에 현업이 확인할 조건과 테스트 방법을 합의합니다. 실제 기준과 허용 수준은 대상 업무의 영향, 데이터 상태와 연계 범위에 따라 정합니다.

INPUT

입력 처리

값이 없거나 오래되었거나 형식이 잘못되었을 때 이를 구분해 표시하는지 확인합니다.

RULE

기준 재현

합의한 계산식과 규칙을 적용하고 사용한 근거를 다시 확인할 수 있는지 검토합니다.

EXCEPTION

예외와 중단

근거가 부족하거나 허용 범위를 벗어나면 결과를 확정하지 않고 사람에게 확인을 요청하는지 봅니다.

ACCESS

권한 통제

허용되지 않은 데이터 접근과 시스템 조치를 막고 필요한 기록을 남기는지 확인합니다.

REVIEW

현업 검토

담당자가 결과와 한계를 이해하고 승인·보류 등 필요한 조치를 할 수 있는지 확인합니다.

FAILURE

연계 실패

시스템 연결이 실패했을 때 중복 처리 없이 상태를 확인하고 다시 진행할 수 있는지 검토합니다.

인수 기준 — 위 항목은 검토 예시입니다. 실제 테스트 시나리오와 기준값, 허용 가능한 오류 범위, 인수 승인 주체는 자료와 업무 환경을 확인한 뒤 합의합니다.

운영 인계

배포 전에 누가 무엇을 바꾸고 확인할지 정합니다

구현 이후에도 업무 기준과 데이터 연결, 권한, 에이전트 설정은 바뀔 수 있습니다. 운영에 넘길 항목과 변경 승인자, 문제가 생겼을 때 중단하고 복구할 절차를 확인합니다.

CUSTOMER

업무 기준과 최종 승인

고객은 적용할 업무 기준과 데이터 사용 범위를 확인하고 최종 승인자와 운영 담당자를 정합니다.

NEX & BRIDGE

합의한 범위의 구현과 검증

넥스앤브릿지는 합의한 업무 흐름과 역할, 구현 요소를 반영하고 함께 정한 방법으로 검증합니다.

OPERATION

변경·중단·지원 범위

변경 요청과 승인, 오류 확인, 중단·복구 절차와 양측의 운영 지원 범위를 따로 정합니다.

운영 지원 — Managed Service와 SLA는 계약에서 정한 대상과 지원 조건, 양측의 책임, 제외 범위에 따라 적용합니다.
